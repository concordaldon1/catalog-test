CONCORD ALDON — INVENTORY UPDATE
================================

FILES
- update_inventory.py: the inventory filtering, validation, backup, and publishing script.
- README.txt: these instructions.

INSTALLATION
1. In GitHub Desktop, open your catalog-test repository.
2. Choose Repository > Show in Explorer.
3. Replace the existing update_inventory.py in the repository's main folder with
   the one in this package.
4. Replace the existing README.txt if you keep it in that folder.
5. Do not replace index.html, inventory.csv, Update Inventory.bat, photos, or
   .gitignore with anything from this package.
6. In GitHub Desktop, commit the changed updater and README, then push to origin.

DAILY USE
1. Export the inventory from RFMS.
2. Copy the RFMS CSV export into the local repository's incoming folder.
3. Double-click Update Inventory.bat.
4. Review the row counts and confirmation prompts. Type Y when ready to publish.
5. The script filters the export, updates the catalog, commits and pushes the
   inventory files, then moves the source export into incoming\processed.

FILTERING RULES
- Style exactly SILVER: included and Type = Vinyl.
- Style exactly GOLD: included and Type = Vinyl.
- A Style exactly four characters long, beginning with Z and followed by three
  letters or digits (for example ZG91): included and Type = Carpet.
- Longer Z styles (for example ZG91 A1C2) and all other styles are excluded.
- Matching ignores capitalization and repeated/leading/trailing spaces.

OUTPUT COLUMNS
Roll Number, Style, Color, Width, Amt Avail, Type

RFMS FIELD MAPPING
- Roll # -> Roll Number
- Style -> Style
- Color -> Color
- Width -> Width
- Qty Avail -> Amt Avail
- Type is generated by the script from Style; no RFMS Type field is needed.

INVENTORY DATE
The script writes inventory_date.txt using the RFMS export file's Last Modified
(timestamp), converted to the local time zone. This is intentional: when the
export is copied from the remote RFMS desktop to this computer, Windows updates
Created and Accessed but preserves Last Modified. The displayed "Inventory as
of" time therefore reflects the export's original modification time, not the
local copy time.

SAFETY / GIT BEHAVIOR
- The original RFMS export is not edited.
- The script requires the local repository to be on branch main.
- It validates required RFMS columns, nonblank roll numbers, and numeric Qty Avail.
- It refuses to publish an empty inventory and warns if the filtered row count
  is less than half the current inventory.
- It backs up the previous inventory in inventory_backups.
- It stages and commits only inventory.csv and inventory_date.txt.
- If both files are unchanged, it skips the empty Git commit and reports that
  no publishing was necessary.
- If pushing fails, the local commit remains; use GitHub Desktop to push origin.
- The source export is archived in incoming\processed only after a successful
  push or a verified no-change run.

LOCAL-ONLY FOLDERS
Keep incoming/ and inventory_backups/ ignored by Git (the repository's
.gitignore should contain those folder names). They remain on your computer and
are not uploaded to GitHub.
